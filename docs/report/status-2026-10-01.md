## 2. 与"日常真用的工具"这个目标的差距

### 2.1 它还没被"日常使用"证明过 `[Verified]`
`hot` 仅 5 条，其中 3 条是 rig 提示词产生。项目判据 1：通电后 4 周内真实 `source='hot'` 运行
**< 30 条 ⇒ 停止加功能**（窗口至 2026-10-29）。⇒ 现在最缺的不是代码，是**真的开始每天用它**。

### 2.2 价值本身没证 —— 唯一的空白 `[Verified]`
已证的只是"块到达了模型"和"改变了召回"。**"注入的经验是否让答案变好"从未测过**
（`agent-os-v2.md §15` 原话）。对"日常真用"而言，这是"值不值得留"的答案。免费模型
`opencode/space-bunny-free` 产不出可测差异。

### 2.3 每天的固定摩擦 = 人门 `[Judgment]`
每次运行结果都要 `review label`。判据 2 已预判：周均待标注 > 50，或连续两周标注 0 ⇒
"人门是主路径"不成立。作为每天用的工具，这是最大体验问题。

### 2.4 环境里有真实的安全隐患 `[Verified]`
`~/.zshrc:87` 的 `alias opencode='… opencode --auto'`。`opencode run --help` 对 `--auto` 的说明是
"auto-approve permissions that are not explicitly denied (**dangerous!**)" ⇒ owner 日常敲 `opencode`
就是在**自动批准当前 cwd 下的编辑与任意 bash**。`live/run.sh` 头注释专门警告"绝不用该 alias"。
让别的 agent 驱动 opencode 测试时，这条会被直接放大。

### 2.5 唯一的"复用现有能力"通路零代码 `[Verified]`
`final-plan §7` 写了只读接入本机 skill-tracker 遥测（`AOS_SKILL_TRACKER_DB`），但
`grep skill-usage|skill_tracker|AOS_SKILL_TRACKER aos/` **无匹配**。这是"复用"诉求里唯一未兑现的一条。

## 3. 要"证明价值"，具体做什么（按顺序）`[Judgment]`

1. **先真的每天用它**，不要跑 rig 凑数（判据 1 只数交互会话）。让 `hot` 自然涨到 30，
   2026-10-29 由 `doctor` 的 `hot` / `recall` 两行判定。
2. **一次盲评 A/B** 回答"是否让答案变好"：任务选"项目特有事实、模型冷启动会答错"的题；
   带环 vs 惰；**判定规则调用前固定**；需要一个能产出差异的模型。
3. **降日常摩擦**：把 `--auto` 从 alias 摘掉/收窄；评估放宽 `min_auto_confidence` 减少每天标注量。
4. **补三个便宜且已验证的缺口**：AK（`user_interrupted` 读了没人写 —— 0 调用普查宿主有无中断事件）、
   AF（rig 的 tee 早于 mkdir，一行）、AI（退出码 → 构建/测试的归属规则，owner 拍板）；
   以及 §2.5 的 skill-tracker 只读接入。
