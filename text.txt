# Phase 5.9.3 — PROJ-001 No-AI Rebuild Architecture Audit

## 一、项目背景

当前真实项目：

```text
project_id: PROJ-001
project_name: aiview
path: /home/shade/Public/test
```

当前项目是：

> AI 面试陪练与智能反馈平台

但现在项目目标发生变化：

> **准备进行一次大规模重构，并且新的项目版本不再使用 AI 功能。**

因此本阶段不是立即重构。

本阶段目标是：

> **完整理解现有系统，并明确“哪些属于 AI、哪些属于核心业务、哪些必须保留、哪些应该删除、哪些需要重新设计”。**

# 十六、Step 13：No-AI Target Architecture

基于前面的事实重新设计目标架构。

目标：

```text
Frontend
   ↓
REST API
   ↓
Spring Boot
   ↓
Domain / Application
   ↓
MySQL
   ↓
Redis / RabbitMQ
```

注意：

> 上面的结构只是分析起点，不允许机械照搬。

必须根据当前项目实际情况判断：

```text
Redis 是否继续需要
RabbitMQ 是否继续需要
```

尤其不要为了“看起来像大厂项目”而保留不必要组件。

# 十八、Step 15：重构策略

不要马上执行。

设计三种：

```text
Option A
Incremental Refactor

Option B
Module Rewrite

Option C
Clean Rebuild
```

分别分析：

```text
Cost
Risk
Migration Difficulty
Code Reuse
Data Migration
Testing
```

最后推荐一个。

# 二十三、重要要求

所有结论必须区分：

```text
FACT
INFERENCE
RECOMMENDATION
```

每个重要判断必须有：

```text
file
class
method
or configuration evidence
```

禁止：

```text
泛化建议
无证据架构设计
为了“高级”而引入微服务
为了“高级”而保留 Redis/RabbitMQ
为了“高级”而拆成多个服务
```

你的目标是：

> **更简单、更清晰、更容易维护的 No-AI 面试训练系统。**

不是：

> 更复杂的系统。
