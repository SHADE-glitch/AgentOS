Systemic Bug: Promotion Pipeline Broken
Root cause: _pattern_to_memory_id() in team_result_collector.py:298 maps technical patterns to P8-{CLEAN_NAME} format (e.g., cache-expiration-pattern → P8-CACHE-EXPIRATION-PATTERN). These P8-xxx memories don't exist in retrieval-index.yaml. The validator M4 check rejects all candidates, so nothing ever promotes.
Impact: The memory feedback loop is completely broken. Agent outputs are captured but never persisted, so the system cannot learn from past analyses.

Recommendations
1. Fix P8-xxx memory creation — Either auto-create pattern memories in the index when collector generates them, or change the collector to target existing memory types (T-xxx, S-xxx)
2. Add M4 bypass for new patterns — Allow promoter to create new memory files for previously unseen pattern IDs
3. Reduce team size — C5 cap of 7 is excessive for most tasks; consider dynamic sizing based on complexity
4. Parallelize TaskCards — Sequential execution is the latency bottleneck; independent agents could run concurrently
5. Improve memory ranking — Cross-run retrieval variance is low; consider intent-weighted ranking
