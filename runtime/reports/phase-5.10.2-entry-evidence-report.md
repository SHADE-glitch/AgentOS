## 1. Previous Weakness

```text
WEAKEST_POINT:
```

**A better approach**: embed entry metadata into the trace itself.

---

## 2. Entry Evidence Design

### 2.1 Schema

```yaml
entry:
  entry_type: "aos_cli"          # aos_cli | direct | unknown
  executable: "/path/to/aos"      # absolute path to aos binary
  command: "aos run"             # CLI command
  entry_timestamp: "ISO8601"     # UTC timestamp at aos startup
  pid: 1747636                   # process ID of aos
  cwd: "/working/directory"      # working directory
  task_id: "AOS-CAB36F"          # task ID generated by aos
```

### 2.2 Data Flow

```
aos (generates entry_metadata)
  ↓ AOS_ENTRY_METADATA env var
loop_controller (reads env, stores in state, passes to runtime)
  ↓ decision_context["entry_metadata"]
runtime_adapter (writes to trace YAML)
  ↓ trace["entry"]
trace file (immutable evidence)
```

### 2.3 No Sensitive Data

Only `entry_type`, `executable`, `command`, `entry_timestamp`, `pid`, `cwd`, `task_id`.  
No API keys, tokens, passwords, credentials, or full environment variables.
